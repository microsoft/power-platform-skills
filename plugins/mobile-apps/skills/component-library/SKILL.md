# Mobile App Component Library

Own reusable React Native UI primitives and composed business-agnostic components. Do not implement complete feature screens or data workflows.

Read [stage-contract.md](../create-mobile-app/references/stage-contract.md), [template-contract.md](../create-mobile-app/references/template-contract.md), and [ux-quality.md](../create-mobile-app/references/ux-quality.md).

## Procedure

1. Require complete authoritative Screen Design specifications, an explicit `Component Map`, `Visual Token Contract`, `Responsive Viewport Contract`, `Screen Shell And Inset Ownership Matrix`, per-screen state/control/form and input-purpose bindings, localization and authentication accessibility contracts, media rights/alternatives, WCAG 2.2 AA readiness evidence, and a rendered `.stages/02-screen-design.html`. Verify every reusable component ID used by a Screen Contract appears exactly once in the map, every represented HTML screen/state anchor matches the Markdown ID, and no component API, token, breakpoint, locale behavior, input semantic, media fallback, or layout invariant must be invented. Review the HTML's representative screens/states before coding and return `BLOCKED` to Stage 2 if any contract is missing, ambiguous, blank, or materially inconsistent. Run `npm run type-check` before the first component edit and return `BLOCKED` on failure. Exclude `src/generated/` from direct inspection or edits.
2. Read `package.json`, `tamagui.config.ts`, existing component imports, and package type declarations only for primitives required by the approved component map. Verify each needed import through the normal TypeScript check; do not run broad `node -e` export-enumeration probes or maintain hard-coded export matrices. Extend or compose installed primitives before introducing a dependency or abstraction.
3. Read [the scaffold manifest](./assets/component-scaffold/manifest.json), implement every Component Map entry owned by `shared component`, map those contracts to scaffold IDs, recursively resolve `requires`, and copy exactly that approved closure's `source` plus optional `files` into `src/components/` while preserving family paths; inject no unrelated manifest entry. Map approved image-led cards, row swipe actions, carousels, and multi-step flows to `data-card`, `swipeable-row`, `content-carousel`, and `step-indicator`; compose filtered search from `search-field` and `adaptive-sheet`, and retain existing `form-field`, `segmented-control`, and `empty-state` contracts. Pull-to-refresh and stack swipe-back are framework primitives owned by Stage 4; never create wrappers for them or use `swipeable-row` for navigation. An approved home gradient maps to `gradient-surface`; preserve its token-driven colors, contrast, direction, and content slots instead of recreating `LinearGradient` in the screen or flattening it to a solid surface. When Stage 2 assigns the repeated dashboard summaries to a shared component, implement one typed compact metric-card contract with label, value, context/trend, tone, action semantics, and responsive states; do not create a page-level dashboard component or four variants. An approved theme-mode control maps to `segmented-control` with controlled `system | light | dark` values and single-choice accessibility semantics; profile loading and sign-out behavior remain screen/application concerns. Return `BLOCKED` to Stage 2 rather than generating a custom wrapper for an entry owned by `framework primitive`, or when a shared component has no required usage Screen ID. A planned date/time input maps to `date-time-field`: preserve its controlled `Date` value/`onChange` API and every manifest-listed platform/type file so web uses the browser picker and native uses `@react-native-community/datetimepicker`; never degrade it to free-form text or a button-only `onPress` proxy. Treat layout infrastructure as a prerequisite, not an optional visual component: the approved component map and shell matrix must identify a screen-shell contract whenever routes hide native headers or own scrolling/fixed actions. Return `BLOCKED` to Stage 2 if that contract is absent; do not invent it here. The selected or implemented shell defines safe-area edge ownership, keyboard avoidance, scroll/list mode, responsive maximum width/gutters, and footer spacing. The scaffold `index.ts` is a source catalog only: never copy it or inject the entire scaffold by default. Create or update the target barrel with only selected named exports and their exported prop/item types. Reuse or adapt a compatible destination file; never overwrite it blindly. Injected files become customer-owned and must not import from the skill.
4. Adapt injected assets or implement missing contracts with native Tamagui themes, tokens, primitives, exported prop/item types, typed variants, callbacks, and content/action slots. Treat the installed Tamagui version, app config, and TypeScript component props as the API authority: use only props/shorthands and compound members accepted by those live types, not React Native longhands or APIs remembered from another Tamagui version. Type dynamic token maps with `satisfies` against the receiving component prop type (for example `NonNullable<ComponentProps<typeof Text>['color']>`) so values do not widen to `string`. Use only registered `ThemeName` values; model selected/error/tone states as typed variants or token-valued props instead of inventing theme names. Do not assume compound members such as `Sheet.Title`; verify each member and compose an accessible `Text` heading when it is absent. After adapting each component or tightly related family, run `npm run type-check`; repair that family before copying or implementing another. Components inherit the existing app theme and default to theme tokens; never hard-code color literals or create a second provider. For semantic colors, accept token-valued props or a typed palette supplied by the app theme. Use the HTML only to preserve approved visual hierarchy, composition, and responsive character; never translate HTML/CSS. Do not alter `PowerAppsProvider` or create a second Tamagui provider.
5. Keep components independent of routes, repositories, mock fixtures, native modules, connectors, and generated services.
6. Cover only approved component families and required layout infrastructure with their semantic, responsive, compact-height, keyboard/pointer, accessibility, localization, autofill/input-purpose, long-content, light/dark/increased-contrast, motion, media-fallback, and interaction states. Implement ARIA on web and React Native accessibility props on native through platform-valid boundaries so unsupported props never leak to the DOM. A record without an action must render a non-pressable container; an actionable record must expose typed button/link intent plus persistent affordance and hover/pressed/focus/disabled states. Toggle, single-choice, progress, field/error, live-state, landmark/heading, list, and decorative-icon contracts must expose accurate names, roles, values/states, grouping, requiredness, announcements, and non-color cues. Components enhance repeated behavior and invariants; they must not prescribe complete page composition. Do not create a shared wrapper that only renames one installed primitive prop, encode a whole screen in a reusable component, or make App Builder stack generic cards/rows to approximate distinct layouts. Retain an abstraction only when it provides a stable semantic contract, repeated composition, accessibility behavior, state handling, safe-area/layout infrastructure, or dependency isolation. Merge components with materially identical props and behavior.
7. Expose every injected or implemented component in the gallery with at least one representative state, and reconcile the gallery inventory one-for-one with the customer-app handoff manifest. Gallery-only usage proves the component contract but does not satisfy its planned production Screen IDs. Do not create a parallel app shell, auth bypass, or second provider tree.
8. Verify direct and transitive imports beneath the shared component boundary. Allow presentation dependencies only; move feature behavior behind typed props and callbacks.
9. Export a customer-app handoff manifest with Component ID, scaffold ID/version, destination, named value/type exports, required production Screen IDs, adaptations, props/events, slots, variants/states, theme tokens or palette inputs, web/native name-role-value-state and visible-affordance contracts, dependencies, and gallery example. This handoff is distinct from the skill-owned source registry. Do not export a component without required production consumers.
10. Compare the gallery contracts and component composition with `.stages/02-screen-design.html` and validate wider-layout behavior against Markdown. Audit the screen shell with a hidden native header, a scrolling route, a virtualized-list route, a keyboard form, and a fixed bottom action: exactly one owner must protect each system-bar edge, and content/footer spacing must not double-apply insets. Then run focused static checks, import-boundary review, and `npm run type-check`. Do not run `npm run web`, `npm run dev`, any `bundle:*`/`build:*` script, or another command that builds or launches the complete app before App Builder has assembled every screen and workflow. Missing layout infrastructure, dependencies, forbidden imports, or unexplained contract divergence block completion.

## Safe Token Extension

Inspect the actual config shape before spreading a token group. The template's `defaultConfig.tokens` may not contain `color`, so initialize that group directly:

```ts
const customConfig = {
	...defaultConfig,
	animations,
	tokens: {
		...defaultConfig.tokens,
		color: { brand: '#126B5D' },
	},
};
```

Never use `...defaultConfig.tokens.color` unless the installed config's types confirm that property exists. Run `npm run type-check` immediately after changing `tamagui.config.ts`.

## Reuse Contract

- Keep state controlled unless the component owns transient presentation state; expose typed values, events, and slots instead of repositories or feature hooks.
- Prefer targeted semantic customization props over an untyped style bag. Defaults must remain valid under light, dark, and custom app themes.
- Export every public props, item, tone, and palette type beside its component.
- Compose installed Tamagui primitives directly in screens when no reusable semantic behavior exists.
- Validate selected components through the customer-owned target barrel, never by importing from this skill directory.

Do not create feature routes, domain repositories, or end-to-end workflows. Native, connector, and Dataverse integration belongs to later stages.
