# Optional Named Directions

These are explicit user-selectable starting points, not automatic defaults or an exhaustive design space. No app-name/industry keyword selects a file. No-brand work derives its design from the actual primary job and context.

| Explicit input | Reference | Starting character |
|---|---|---|
| `--direction inspection` | [Inspection](./direction-inspection.md) | High-contrast, large-target utility |
| `--direction polished-inspection` | [Polished inspection](./direction-polished-inspection.md) | Light surfaces, green accent, visible status |
| `--direction saas` | [SaaS](./direction-saas.md) | Familiar internal-tool treatment |
| `--direction product` | [Product](./direction-product.md) | Content/type-led, spacious treatment |
| `--direction airline` | [Airline](./direction-airline.md) | Navy/light operational treatment |

Read only the selected file. Apply the user's requested character while adapting hierarchy, composition, media, and density to the task. Shared accessibility, supported native/font capabilities, and explicit user requirements outrank optional preset advice.

For `--direction <custom description>`, use the supplied description as design input. Do not construct a path from arbitrary user text. Unsupported names need clarification or a clearly disclosed interpretation, never a silent default.

A brand book or an already-clear direction does not need a comparison gallery. [Optional style comparison](./style-picker.md) is available when the user asks to see alternatives. The comparison may contain as many options as needed for that request, not a mandatory set of three.

Keep the result in the compact brand spec and existing plan's `## Design`. Reconcile a legacy `## Design Direction` when present; no duplicate design bundle is required.
