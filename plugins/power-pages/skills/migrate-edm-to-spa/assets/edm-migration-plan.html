EDM vs. SPA — What's Different

A quick reference for users new to the SPA code-site model. Each row shows how a Power Pages concept changes when the site moves off the classic Enhanced Data Model runtime.

Concept Classic EDM (today) Static SPA (target)
Rendering Server-rendered HTML built by the portal runtime from Web Pages, Web Templates, and Liquid. Client-rendered React/Vue/Angular/Astro. Static assets ship to the CDN; the browser fetches data via the Dataverse Web API.
Pages & routes Pages live as web-pages/ records with hierarchical parent/child relationships; the portal maps URLs to pages at runtime. Routes are defined in the framework's router (e.g., React Router, Vue Router). The hierarchy is code, not Dataverse data.
Layouts & composition Web Templates with Liquid {% include %} directives compose the page server-side. Component composition via JSX/SFC/Astro syntax. Shared layouts are AppShell/Layout components, not Liquid includes.
Reusable content Content Snippets — records in Dataverse, referenced via {{ snippets['name'] }}. Content constants, content modules, or localization resources imported at build time.
Data access Liquid Dataverse helpers ({% fetchxml %}, {% entityview %}) execute server-side; entity lists/forms read from Dataverse implicitly. Explicit client-side fetch calls to the Power Pages Web API (/_api/<table>) using table permissions and the anti-forgery token from /_layout/tokenhtml.
Forms Basic Forms / Advanced Forms are server-rendered. Validation, anti-forgery, and CRUD are wired by the portal runtime. Client-side form components (e.g., React Hook Form) backed by Web API POST/PATCH calls. CAPTCHA, attachments, and multi-step flows are explicit caveats.
Authentication Configured via Site Settings + identity provider records; the portal handles the redirect flow. Wired by /setup-auth — MSAL.js (or framework equivalent), sign-in/sign-out routes, AuthButton in the AppShell, route guards.
Authorization Web Roles + Table Permissions enforced by the portal runtime; {% if user.roles contains 'X' %} in Liquid. Server-enforced still — table permissions in Dataverse remain the authority. Client-side RequireRole guards are UX hints, not security boundaries.
Server-side logic Liquid blocks that read privileged context or use server-only helpers. /add-server-logic deploys server endpoints; the SPA calls them like any other service.
Site settings & metadata Aggregate YAML records (sitesetting.yml, webrole.yml, sitemarker.yml) — many records per file. Granular per-record files under .powerpages-site/ (one file per setting / role / marker). Same data, different shape.
Assets & images web-files/ records with binaries attached; served by the portal runtime. Files copied to public/ (or src/assets/ for bundler-imported), referenced by static paths or import statements.
Customization Custom JS sidecars on web pages / lists / forms; jQuery, Page_Validators, portal-runtime globals. First-class component source under src/; standard ESM modules; framework idioms (hooks, composables, signals).
Deployment pac pages download / pac pages upload against Dataverse records. npm run build + pac pages upload-code-site; hydrates .powerpages-site/ metadata once activated.
