## Known gaps (correctly flagged by the runner)

The runner emits 6 failures against this fixture. Each is real signal about
agent behavior — not runner inaccuracy.

**Layer 1 — workflow-log compactness (5 failures):**

| Failing assertion | Why |
|---|---|
| `node --version + pac help separately + version verified` | Log records `Auth: <user>` (the outcome) but not the prereq commands themselves |
| `pac auth list ... reported to user` | Same — outcome is logged, command is not |
| `Question 1 (new or edit) via AskUserQuestion` | Log says `Decision: new page` (the outcome) without recording the AskUserQuestion call |
| `Plan presented via EnterPlanMode` | Log says `Plan written` without recording the EnterPlanMode call |
| `pac model genpage upload --prompt scoping` | Phase 6 records `Command: pac model genpage upload --add-to-sitemap` — the actual flags (including `--prompt`) aren't in the log |

The agent producing this capture writes a **decision/outcome-summary** style
workflow-log. The v2.1 assertions assume a **command-level audit-trail**
style. Both styles are reasonable; the assertions are calibrated to the
latter because it's debuggable in isolation.

**Layer 2 — code-gen rule (1 failure):**

| Failing assertion | Why |
|---|---|
| `Destructures props including pageInput` | The page uses `void props;` rather than `const { pageInput } = props;`. The rule applies to all pages including mock-data pages. |

## What was done about the gaps

**Path 1 (spec tightening) was taken** — see commits on this branch following
the capture. Changes:

- `agents/genpage-planner.md` — added a "Workflow-log requirements" section
  before Step 1, explicitly requiring command-level entries (verbatim
  `node --version`, `pac auth list`, `AskUserQuestion: <text> → <answer>`,
  `EnterPlanMode called`, etc.).
- `skills/genpage/SKILL.md` Phase 6 — added a required log-template that
  echoes the full `pac model genpage upload` command including `--prompt`
  and all other flags before invocation.
- `skills/genpage/SKILL.md` Phase 8 — replaced the vague "summarizing the
  run" template with an explicit per-phase format and a callout that
  decision-only logs fail the assertions.
- `agents/genpage-page-builder.md` — promoted the `pageInput` destructure
  rule to the top of the Mandatory Rules list with explicit "even on
  mock-data pages" + "`void props;` is forbidden" emphasis.

**This fixture stays red** until a future `/genpage` run for eval 2
re-captures the workflow under the tightened spec. The captured artifacts
predate the spec change, so re-grading them would be retroactive.

against the older spec. To re-capture and flip both layers green:
